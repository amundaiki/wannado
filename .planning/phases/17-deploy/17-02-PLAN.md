  <action>
1. Add the wannado.no domain to the Vercel project:
   ```
   vercel domains add wannado.no --yes
   ```

2. Also add www.wannado.no so it redirects to the apex domain:
   ```
   vercel domains add www.wannado.no --yes
   ```

3. Get the DNS configuration that Vercel requires. Run:
   ```
   vercel domains inspect wannado.no
   ```
   This will show the required DNS records. Typically for apex domains:
   - A record: `76.76.21.21`
   - Or CNAME: `cname.vercel-dns.com` (for www subdomain)
   
   Record the exact DNS values Vercel requests, as these are needed for the human checkpoint.

4. Deploy to production:
   ```
   vercel --prod --yes
   ```

5. Document the exact DNS records needed for the checkpoint task.

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: DNS cutover at hosting provider</name>
  <action>
The user must update DNS records at their current hosting provider (Apache with Varnish-cache). The old WordPress site is at https://wannado.no/.

**Required DNS changes (exact values from Task 1):**

For the apex domain `wannado.no`:
- Change A record to: `76.76.21.21` (Vercel's IP, confirmed from `vercel domains inspect`)

For `www.wannado.no`:
- Add/change CNAME record to: `cname.vercel-dns.com`

**Steps for the user:**
1. Log in to your DNS provider/registrar dashboard (where wannado.no is registered)
2. Find DNS settings for wannado.no
3. Update the A record for `@` (root) to `76.76.21.21`
4. Add or update CNAME for `www` to `cname.vercel-dns.com`
5. Save changes
6. DNS propagation typically takes 5-30 minutes, can take up to 48 hours

**Important:** The old WordPress site will go down once DNS changes propagate. Make sure you are ready for the cutover. Consider doing this during low-traffic hours.
  </action>
  <resume-signal>Type "dns-updated" once you have saved the DNS changes at your hosting provider. If the DNS values from Task 1 differ from what is listed here, share the correct values first.</resume-signal>

<task type="auto">
  <name>Task 3: Verify production SSL, redirects, and Core Web Vitals</name>
  <files></files>
  <action>
1. Wait briefly for DNS propagation, then verify DNS points to Vercel:
   ```
   dig wannado.no A +short
   dig www.wannado.no CNAME +short
   ```
   Expected: `76.76.21.21` for A record, `cname.vercel-dns.com` for CNAME.

2. Verify SSL certificate is active:
   ```
   curl -sI https://wannado.no | head -20
   ```
   Check for HTTP/2 200 and valid certificate. Vercel auto-provisions Let's Encrypt SSL.

3. Verify www redirects to apex:
   ```
   curl -sI https://www.wannado.no -o /dev/null -w "%{http_code} %{redirect_url}"
   ```
   Should 301/308 redirect to https://wannado.no.

4. Test 301 redirects in production (old WordPress URLs):
   ```
   curl -s -o /dev/null -w "%{http_code}" https://wannado.no/kulturvandring-med-sjarmerende-treskoyte
   curl -s -o /dev/null -w "%{http_code}" https://wannado.no/kajakk-turer-og-ekspedisjoner
   curl -s -o /dev/null -w "%{http_code}" https://wannado.no/kurs/kajakkurs
   ```
   All should return 301.

5. Test key routes in production:
   ```
   for route in / /seilturer /kajakkturer /teambuilding /foredrag /kontakt /sitemap.xml /robots.txt; do
     echo "$route: $(curl -s -o /dev/null -w '%{http_code}' https://wannado.no$route)"
   done
   ```
   All should return 200.

6. Run Lighthouse CLI for Core Web Vitals (if available), or use PageSpeed Insights API:
   ```
   npx lighthouse https://wannado.no --output=json --only-categories=performance --chrome-flags="--headless --no-sandbox" 2>/dev/null | grep -E '"(score|first-contentful-paint|largest-contentful-paint|cumulative-layout-shift|total-blocking-time)"'
   ```
   Target: Performance score 90+, LCP < 2.5s, CLS < 0.1.

   If Lighthouse CLI is not available or errors, use curl to check PageSpeed Insights:
   ```
   curl -s "https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=https://wannado.no&strategy=mobile&category=performance" | python3 -m json.tool | grep -E '"(score|id)"' | head -20
   ```

7. If any check fails, investigate and fix. Common issues:
   - SSL not yet provisioned: Wait 5-10 minutes, Vercel auto-provisions
   - DNS not propagated: Wait and retry
   - Redirect loops: Check vercel.json and next.config.ts for conflicts
   - Contact form returns success but no e-mail arrives: configure `RESEND_API_KEY` in Vercel project settings
  </action>
